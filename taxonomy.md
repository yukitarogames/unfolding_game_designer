## 1. What is an "unfolding" incremental game?

**Incremental game:** A game where the core loop is accumulating resources that are spent to increase the rate of further accumulation, producing growth that the player steers rather than directly performs.

**Unfolding incremental game:** An incremental game whose main source of delight is the *progressive reveal* of new mechanics, systems, and scope. The game starts small and minimal, and repeatedly expands what the player understands the game to *be*.

- The number going up is the engine; **the game changing shape** is the payoff.
- The player should regularly ask "wait, there's *more*?"

## 2. Core economy terms

| Term | Definition | Notes |
|------|------------|-------|
| **Resource** | Any quantity the player accumulates and spends (currency, materials, points). | |
| **Primary resource** | The first resource the player meets; usually the main measure of progress early on. | |
| **Generator** | Something that produces a resource over time without player action. | |
| **Producer chain / tier** | Generators that produce other generators (e.g. tier 2 makes tier 1). | |
| **Manual action** | A player action that produces value directly (click, craft, explore). | |
| **Upgrade** | A one-time purchase that permanently modifies a rule or rate. | |
| **Multiplier** | An upgrade or effect that scales output multiplicatively. | |
| **Cost scaling** | How the price of repeatable purchases grows (linear, polynomial, exponential). | |
| **Rate** | Resource gained per unit time. | |
| **Sink** | Anything that consumes a resource, removing it from the economy. | |
| **Conversion** | Turning one resource into another, often at a lossy or changing ratio. | |
| **Cap / storage limit** | A ceiling on how much of a resource can be held. | |

## 3. Unfolding & reveal terms

| Term | Definition | Notes |
|------|------------|-------|
| **Unfold** | A moment where a new mechanic, system, or area becomes visible and the game's scope expands. | |
| **Reveal** | Showing the player something previously hidden (UI panel, resource, mechanic). | |
| **Unlock condition** | The trigger for a reveal (threshold reached, item bought, time elapsed, action discovered). | |
| **Teaser / foreshadowing** | A hint that something exists before it is available (greyed-out button, `???`, cryptic text). | |
| **Scope shift** | An unfold that changes the *scale* or *frame* of the game (e.g. from a single shop to a city). | |
| **Mechanic introduction** | An unfold that adds a new verb or system, not just a new number. | |
| **Recontextualization** | An unfold that changes the meaning of earlier systems. | |
| **Hidden mechanic** | A system that exists but is never or only late explained; discovery is part of the play. | |
| **Unfold cadence** | How often unfolds happen; the rhythm of novelty over a playthrough. | |

## 4. Structural terms

| Term | Definition | Notes |
|------|------------|-------|
| **Layer** | A distinct tier of progression with its own resources and loop, built on the previous one. | |
| **Prestige / reset** | Voluntarily resetting progress in exchange for a permanent bonus or new currency. | |
| **Era / act / phase** | A narrative or thematic segment of the game, usually bounded by major unfolds. | |
| **Milestone** | A notable threshold that grants a reward or reveal. | |
| **Gate** | A requirement that blocks progress until met. | |
| **Bottleneck** | The current limiting factor on progress; the thing the player is optimizing. | |
| **Automation** | Mechanics that take over previously manual tasks, freeing attention for new ones. | |
| **Endgame** | The final phase, after which no new unfolds occur. | |
| **Ending** | A defined conclusion (many unfolding games have one, unlike endless idlers). | |

## 5. Pacing & player experience terms

| Term | Definition | Notes |
|------|------------|-------|
| **Pacing** | The rate at which progress, rewards, and unfolds are delivered. | |
| **Wall** | A point where progress slows sharply, forcing a new strategy or waiting. | |
| **Dead time** | Periods where the player has nothing meaningful to do or decide. | |
| **Active vs. idle play** | Whether progress requires attention or happens while away. | |
| **Offline progress** | Progress earned while the game is closed. | |
| **Decision density** | How many meaningful choices the player makes per unit time. | |
| **Sense of mystery** | The player's ongoing belief that more remains to be discovered. | |
| **Power fantasy** | The satisfaction of trivializing what was once hard. | |
| **Session length** | Typical duration of one sitting. | |
| **Total playtime** | Expected time to reach the ending. | |

## 6. Presentation terms

| Term | Definition | Notes |
|------|------------|-------|
| **Minimal start** | Beginning with almost nothing on screen (a single button or line of text). | |
| **UI growth** | The interface itself expanding as part of the unfold. | |
| **Flavor text / narrative log** | Text that carries story, tone, or hints alongside mechanics. | |
| **Number notation** | How large numbers are displayed (scientific, suffixes, etc.). | |

## 7. Anti-patterns (named failure modes)

| Term | Definition | Notes |
|------|------------|-------|
| **Number-only progression** | Growth with no new mechanics; the game stops unfolding. | |
| **Unfold drought** | Too long between meaningful reveals. | |
| **Front-loaded reveal** | Showing too much too early, killing mystery. | |
| **Grind wall** | A wall solvable only by waiting, with no decisions. | |
| **Orphaned mechanic** | A system introduced and then made irrelevant without payoff. | |
| **Automation too late** | Forcing tedious manual actions after they've stopped being interesting. | |
